# F8 Timing

This chapter specifies the ATF15xx timing data: the datasheet timing model, the speed-grade
values the vendor fitters use, and how the vendor composes the delays it back-annotates (SDF). It
is what a timing analyser or a timing-driven fitter needs. Evidence levels as in F2: **[O]**
oracle-verified (the fitters' SDF output), **[E]** external (datasheet), **[I]** inferred.

Machine-readable data: `atf15xx-arch/data/timing.json`, generated by
`tools/fuzzers/fitter-timing/derive_timing.py` from the datasheets and the fitters' SDF output;
every value records its evidence per grade.

## F8.2 Timing model (datasheet)

```
             ┌─ tIOE ─┐ ┌─ tGLOB (global clock/clear/OE networks) ─┐
 pin ─ tIN/tIO ─ tUIM ─┬─ tLAD (product term) ─┬─ tPEXP (per cascade stage) ─ XOR ─┬─ register: tSU/tH, tRD, tPRE/tCLR ─┬─ tOD1/2/3 ─ pin
   (tFIN fast input ───┼────────────────────────┼───────────────────────────────────┤  (fast input path: tFSU/tFH)        │  tZX1/2/3, tXZ
    to register)       ├─ tLAC (PT control: CE, AR, AP, OE, PT clock) ── tIC/tEN   └─ tCOMB (combinatorial) ────────────┘
                       └─ tSEXP (foldback: NAND term back to the UIM)
                                                              + tRPA on tLAD, tLAC, tIC, tACL, tSEXP in reduced-power mode
```

| parameter | meaning |
|---|---|
| tIN / tIO / tFIN | dedicated-input / I/O-pin / fast-input pad and buffer delay |
| tUIM | universal interconnect (switch matrix) delay |
| tLAD / tLAC | logic array delay (sum terms) / logic control delay (PT-driven CE, AR, AP, OE, clock) |
| tSEXP / tPEXP | foldback term delay / cascade logic delay (per stage) |
| tIOE | internal output-enable delay |
| tOD1 / tOD2 / tOD3 | output buffer: fast slew 5.0 V / fast slew 3.3 V / slow slew |
| tZX1 / tZX2 / tZX3 / tXZ | output enable (same three conditions) / output disable |
| tSU / tH, tFSU / tFH | register setup/hold, from the array / from the fast input |
| tRD / tCOMB | register clock-to-output / combinatorial bypass delay |
| tIC / tEN | array (PT) clock delay / register (clock) enable time |
| tGLOB | global control delay (GCLK, GCLR, GOE networks) |
| tPRE / tCLR | register preset / clear time |
| tRPA | reduced-power adder (`MC_power on`, `LowPower` fuse): add to tLAD, tLAC, tIC, tACL, tSEXP |

### F8.2.1 Path equations [E]

The datasheet's internal parameters compose to its pin-to-pin parameters. Checked by
`tools/fuzzers/fitter-timing/timing_paths.py` (ATF1508AS values):

| pin-to-pin | path | -7 | -10 | -15 | -20 | -25 |
|---|---|---|---|---|---|---|
| tPD1 (input → combinatorial output) | tIN + tUIM + tLAD + tCOMB + tOD1 | = | = | = | 18 < 20 | 20 < 25 |
| tCOP (global clock → output) | tIN + tGLOB + tRD + tOD1 | = | = | = | = | 11 < 13 |
| tSU (global-clock setup, pin) | tIN + tUIM + tLAD + tSU − (tIN + tGLOB) | = | = | = | 13 < 16 | 15 < 20 |
| tACOP (array clock → output) | tIN + tUIM + tIC + tRD + tOD1 | = | = | = | 18 < 20 | 20 < 25 |
| tCNT (register → register, global clock) | tRD + tUIM + tLAD + tSU | = | = | = | 16 < 17 | 18 < 22 |

"=" means the sum equals the datasheet value exactly. At -20 and -25 the pin-to-pin values carry
margin over the sum, so **a timing analyser must use the composed path delay but never report less
than the datasheet pin-to-pin value for the same path class.** (tASU does not follow a simple sum.)

## F8.3 Speed-grade values

### F8.3.1 Derivation

`tools/fuzzers/fitter-timing/derive_timing.py`:

1. every AC-characteristics row of the datasheets of F8.1, truncated to whole ns as the fitters'
   output shows they are (7.5 → 7, 1.5 → 1, 0.5 → 0, 0.8 → 0) **[E]**; a grade that no datasheet
   of the family covers is taken from the nearest family (1504AS -15/-20 from the 1508AS) **[I]**;
2. every SDF delay that is a single parameter (F8.4: AND = tLAD, OR = tPEXP, TRI = tOD1 / tXZ,
   register = tRD / tCLR / tPRE / tEN / tSU / tH) sets that parameter, all five grades, to the
   fitter's value **[O]**;
3. every SDF delay of the corpus must then be one of the compositions of F8.4: 6,895 of 6,895 are.

Where the fitter's SDF disagrees with the truncated datasheet value, the fitter's value is used:
1502 tOD1 -15 (4, datasheet 5) and -25 (7, 6), tXZ -25 (7, 8), tCLR / tPRE / tSU / tH -25 (5, 6);
1504 register tSU -10 (2, datasheet 3; 2 is also the value consistent with the 1504 datasheet's
own pin-to-pin tSU, F8.2.1). For parameters no SDF delay shows, the datasheet value is used.

### F8.3.2 Speed-grade selection

`-strategy tPD = N` selects the grade: 7, 10, 15, 20, 25 give the five grades of the corpus; the
help text offers `[ 15 | 7 | 10 | 12 | 25 ]`, and 5, 7 and 12 (and no option) give identical SDF,
i.e. the -7 values. **[O]**

### F8.3.4 The fitters' internal values

Until 2026-11-25 this table was a copy of tables read out of the fitter binaries. The derived table
differs from that copy in 12 values, all of parameters no SDF delay shows: the 1502 -25 column of
tEN, tIC, tFH, tFSU, tPEXP, tRPA, tZX1–3 (datasheet 1 ns slower), 1502 tCNT / tACNT at -20 (16, not

specification of the silicon.

## F8.4 Vendor SDF back-annotation [O]

`-strategy Verilog_sim sdf` writes `<design>.vo` (a gate-level Verilog netlist of `AND<n>`, `OR<n>`,
`XOR2`, `INV`, `BUF`, `TRI`, `DFFEARS`, `TFFEARS`, `LATCH` … cells with `$sdf_annotate`) and
`<design>.sdo` (SDF 1.0, `TIMESCALE 1ns`, integer delays `(v:v:v)` for rise and fall).
`-strategy Vhdl_sim sdf|vhdl` writes the VHDL equivalent (`.vho`; generics `treg`, `trsu`, …).

Every cell delay in the corpus is one of the following compositions of the F8.3 values for the
grade (each delay followed across all five grades):

| cell / path | delay |
|---|---|
| `BUF` A→Q, input pin or feedback into the array | tIN + tUIM |
| `BUF` A→Q, global network (GCLK, GCLR, GOE) | tIN + tGLOB |
| `BUF` A→Q, combinatorial output bypass | tCOMB |
| `INV` A→QN (inverted array input) | tIN + tUIM |
| `AND<n>` (product term), any input | tLAD |
| `OR<n>` | 0 in the whole corpus (widest OR: 5 inputs); tPEXP per cascade stage is the datasheet model **[E]** |
| `XOR2` | 0 |
| foldback expander: its `AND`, `BUF` and `INV` cells | 0, and the closing `INV` carries tSEXP |
| `TRI` A→Q / EN→Q | tOD1 / tXZ |
| `DFFEARS`, `TFFEARS`, `LATCH`: CLK (EN)→Q, AR→Q, AS→Q | tRD, tCLR, tPRE |
| register `SETUP` / `HOLD` (D or T, or latch D) | tSU / tH |
| register CE | no CE path is printed; tEN from the datasheet **[E]** |

**[O]**: `tools/fuzzers/fitter-timing/check_sdf_timing.py` explains every one of the 6,895 cell delays (each
followed across all five grades: 34,475 values) in 260 vendor SDF files (`tools/fuzzers/fitter-timing/sdf_corpus.sh`: 12 feature designs + cascade + foldback +
reduced power + fast slew per family, and the user designs `spi`, `input`, `rpi-pico-8088`,
`system-controller`, each at all five grades).

### F8.4.1 What the vendor model leaves out [O]

No delay of the corpus involves tIO, tFIN, tLAC, tIOE, tOD2, tOD3, tZX1–3, tFSU, tFH, tIC or tRPA.
Consequently (all **[O]**: identical SDF with and without the option):

* **slow slew is ignored**: outputs are annotated with tOD1 even though slow slew (`Slew` fuse = 1)
  is the vendor default unless `output_fast on`; real output delay is tOD3 (-7: 5 ns, not 2);
* **reduced power is ignored**: `MC_power on` adds tRPA (10–15 ns) to every array path in silicon,
  but not in the SDF;
* PT clocks get tRD only (no tIC), PT control terms get tLAD (not tLAC), output enable gets tXZ
  (not tZX), and the fast-input register path is not modelled;
* integer truncation makes -7/-10 paths up to ~2 ns optimistic (tIN 0.5 → 0, tPEXP 0.8 → 0).

The vendor SDF is therefore a functional-simulation aid, not a sign-off timing model.

## F8.5 Timing model for our tools (normative)

An open timing analyser for fitted designs shall (implemented: `atf15xx-sim timing`, `atf15xx-sim/src/timing.rs`, and the flow's `<top>.timing.rpt` / `--fmax`; §F8.6):

1. take parameter values from the datasheet (fractional ns; `timing.json` gives the truncated
   values the fitters use);
2. compose each path from the F8.2 model using the fitted configuration from the JED (F2):
   input pin tIO (dedicated input tIN, fast input tFIN), tUIM per pass through the interconnect,
   tLAD per sum (plus tPEXP per cascade stage, plus tSEXP + tUIM per foldback), tLAC/tIC for
   PT-driven controls and clocks, tGLOB for global networks, tRD/tCOMB, and tOD1/tOD2/tOD3 (or
   tZX/tXZ) by slew fuse and VCCIO;
3. add tRPA to tLAD, tLAC, tIC, tACL and tSEXP of macrocells with `LowPower` set;
4. report each pin-to-pin path as max(composed, the datasheet's pin-to-pin value of its class)
   (F8.2.1), and the register-to-register period from tRD + tUIM + tLAD (+ cascades/foldbacks) + tSU;
5. say which grade and VCCIO it assumed.

## F8.6 Implementation and silicon check (2026-11-24)

`atf15xx-sim timing X.jed -d DEVICE [--grade -10] [--vccio 5|3.3] [--map X.map.json] [--fmax MHz]`
times any fuse map, ours or the vendor's, from the decoded configuration. The flow writes
`<top>.timing.rpt` and prints fmax in its summary. With `--fmax`, the flow tries its
strategies until one meets the target, adding wider-sum strategies (`max_products` 15/20/25:
cascades cost tPEXP per stage instead of tUIM + tLAD + tCOMB per level). It keeps the best fit
and exits with status 2 if none meets the target.

Arrival times: a signal at the UIM input is a pin (tIN dedicated, tIO I/O), a register Q (tRD
after its clock), or a combinatorial feedback (x + tCOMB). Each PT literal adds tUIM (one "UIM
pass"), a foldback line adds tSEXP after its PT1 inputs, and a sum adds tLAD after its latest PT,
plus tPEXP per cascade stage. The XOR's PT2 path is a PT + tLAD. The D input is x (T flip-flop: x
⊕ own Q, no UIM pass), PT2 (fast path, tSU), or the pad (tFIN, tFSU). The clock enable is PT4 +
tLAC. Global clocks arrive at tIN + tGLOB, PT clocks at PT4 + tIC. `LowPower` macrocells add tRPA.
Floors (F8.2.1): period ≥ tCNT, tPD ≥ tPD1, tCO ≥ tCOP (tACOP for PT clocks), tSU ≥ tSU_global
(tFSU_global for fast inputs).

Approximations: all global clock networks arrive together (no skew); asynchronous
reset/preset paths and latches are not timed; a pin driven by its own macrocell is read as an
external input; values are the vendor's whole-ns tables (F8.3), so results near a limit have
about 1 ns of rounding.

Silicon (the bench's **ATF1508AS-10JU84**, speed grade -10 per the user; 66.6 MHz oscillator): our Verilog `vblink` fits at **32.3 MHz** (3 UIM passes) and
**38.5 MHz** (current default) both fail to run at 66.6 MHz. The `--max-products 15` fit
(**100 MHz**, 1 pass) and the `--fmax 66.6` fit (**66.7 MHz**, chosen by the flow) both run: P4
toggles at 33.5 Hz = 66.6 MHz / 2·10⁶.

## F8.7 Timing targets and the area/speed trade (2026-11-25)

Timing is part of what the flow optimises, not only a report. Targets come from the constraints
file (`.acf`) or the command line (`--fmax` overrides `fmax`, `--optimize` overrides `optimize`):

```text
fmax     66.6        # register-to-register, every clock (MHz)
clock    clk 66.6    # registers captured by one clock port (MHz; global clock networks)
tpd      21          # worst pin-to-pin delay (ns)
tco      12          # worst clock-to-output (ns)
tsu      8           # worst input setup (ns)
optimize area        # or speed
```

**Selection** (`atf15xx_fit::search::judge` and `fit_key`, shared by the strategy loop, the wide-compare
piece forms (F9.12) and `flow::better` across mappings):

1. A fit that meets every target beats one that does not, **whatever it costs in macrocells**.
   This is the "two levels of logic cost more area but close timing" rule. When a target is
   given, the strategy queue also contains the wider-sum strategies (`max_products` 15/20/25:
   cascades at tPEXP per stage instead of tUIM + tLAD + tCOMB per extra level), tried when the
   area-first ones miss.
2. Of fits that all miss the targets, the one that misses by less (since 2026-11-26): the worst
   relative shortfall over all targets, `(want − got) / want` for a frequency, `(got − want) /
   want` for a delay (1 for a clock target that cannot be measured). Before, missed fits ranked
   by area: a 10-bit registered compare on the ATF1502AS asked for 55 MHz got 26 MCs at 41.7 MHz
   although a 31-MC, 52.6 MHz fit was among the candidates (asked for 50 MHz it got that one); now
   it gets 52.6 MHz. Unit test `missed_targets_rank_by_shortfall`.
3. Among fits that meet the targets (or without targets): `optimize area` takes the fewest
   macrocells, then the highest fmax, and stops at the first strategy that meets the targets.
   `optimize speed` takes the highest fmax, then the fewest macrocells, and scans the
   strategies (without shuffled orders) for the best one.
4. Missed targets are reported with each violation (`timing targets missed: tPD 21.0 ns > 10.0
   ns`), the best fit is still written, and the CLI exits with status 2.

The register-to-register paths carry the pin of the capturing global clock (`RegPath::clock_pin`),
so per-clock targets check `Report::period_for_clock`. PT-clocked registers count only towards
`fmax`.

Checked: vblink with `clock clk 66.6` picks the 66.7 MHz fit; mux16 with `tpd 10` reports the
miss (its 8-bit `a < b` needs two levels, 21 ns: one level would need the per-bit equality
terms flattened in, exponentially many products; the one-level floor tPD1 is 10 ns at -10).

**Foldback depth** (2026-11-25). A shared OR node `N = p1 + … + pk` turned into foldback signals
(`nodes_to_foldbacks`) gives inner foldbacks `fi = !pi`. `!N = f1·…·fk` is one foldback
level, but `N` itself is the foldback of foldbacks: two levels, 2·tSEXP. With a timing target, the
capacity strategies also come limited to one level (`Strategy::fold_one_level`,
`Design::nodes_to_foldbacks_with(…, true)`): nodes read positively stay macrocell nodes (one UIM
pass, tUIM + tLAD + tCOMB), which is faster and may cost macrocells. SELFPROGRAMBOARD from
Verilog ran at 33.3 MHz because its counter clock-enable read `SPI_Count_Enable` through two
levels. The one-level variant alone runs out of macrocells for foldback expanders (a block hosts
at most 16, one per PT1, and the expanders are replicated per reading block).

**SELFPROGRAMBOARD above 50 MHz** (2026-11-25). WinCUPL's netlist (55.6 MHz through our fitter)
keeps its clock-enables as shared macrocell nodes (`MISO0_CE$`, `MOSI0_CE$`, …), two UIM passes
and no foldback delay, and pays for them with logic doubling: 9 macrocells pair an output with a
buried register, against our 5. Our netlist could double as much, but only with D flip-flops:
toggle recovery made those registers 2-product T flip-flops, which a doubled macrocell cannot
take. Three changes:

1. a fourth capacity strategy, **no foldback signals and no toggles**: the shared control
   functions stay macrocell nodes, and the registers stay D flip-flops, which doubling pairs;
2. the vendor-style collapse converts nodes to foldback signals only when the strategy asks for
   them (`special_foldback`); before, it always did, so "no foldback signals" was not true;
3. once the capacity strategies are queued (a dense design), **all of them are fitted** and the
   best kept: fewest macrocells, then the highest fmax (they tie on area and differ in speed).

Result, by default with no flags and no target: **60 macrocells at 52.6 MHz** (-10), in both
mappings, against 50.0 MHz for WinCUPL + the vendor fitter and 33.3 MHz before. Worst path 19 ns,
two UIM passes (`SPI_Prescaler1` → the counter clock-enables). It matches the Verilog: BOUNDED 25
+ sim 4000.
