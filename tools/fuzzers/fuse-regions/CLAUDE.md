# fuse-regions: supervising a run

Read `../common/CLAUDE.md` first. The Load output is ATMISP's own text: it stays in `.scratch/`;
only `regions.json` (our table of addresses and lengths) is used downstream, and it is not
committed either (it is an input of the fitter experiments, regenerated by this workflow).

* Check the printed totals: PT rows 32·5 / 64·5 / 128·5 per family plus the configuration fields
  must add up to QF 16808 / 34192 / 74136. A different total means the NOTE format changed or a
  field was missed: fix the parser, do not edit `regions.json` by hand.
* Without the labels file (first run, before any fitter experiment), the PT numbering rests on
  atf15xx-arch alone; re-run with `.scratch/re/vendor_labels.json` once the fitter corpus exists. An
  assertion naming a row means atf15xx-arch and the fitter disagree: stop and report it.
* Record the totals and the number of checked rows in `docs/worklog/02-fitter.md`.
